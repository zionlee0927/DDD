# 03. Bounded Context 경계

> "Bounded Context는 특정 모델이 정의되고 적용되는 경계를 명시적으로 설정한다." — Eric Evans

---

## 식별 과정

### 입력

- 0단계 서브도메인 목록
- 1단계 용어집 (같은 용어가 다른 의미로 쓰이는지)
- 2단계 이벤트 (어떤 이벤트들이 함께 발생하는지)

### 경계를 나타내는 6가지 신호

| 신호 | 질문 | 분리 시그널 |
|------|------|-------------|
| 언어의 변화 | 같은 용어가 다른 의미로 쓰이는가? | "링크"가 URL vs 귀속 증거 |
| 팀/조직 경계 | 다른 팀이 담당할 수 있는가? | 정산팀 vs 추적팀 |
| 변경 주기 | 변경 빈도가 다른가? | 커미션 규칙(주 단위) vs 귀속 전략(분기) |
| 비즈니스 역량 | 독립적으로 가치를 제공하는가? | "귀속을 판정할 수 있다" |
| 데이터 소유권 | Source of Truth가 어디인가? | 클릭 데이터 → Tracking BC |
| 트랜잭션 경계 | 강한 일관성이 필요한 범위는? | 커미션 산정은 귀속과 별도 트랜잭션 |

### 합칠지 분리할지 판단

| 질문 | 합침 | 분리 |
|------|------|------|
| 같은 유비쿼터스 언어를 쓰는가? | ✓ | ✗ |
| 항상 함께 변경되는가? | ✓ | ✗ |
| 같은 팀이 소유하는가? | ✓ | ✗ |
| 하나 없이 다른 하나가 의미 없는가? | ✓ | ✗ |
| 변경 주기가 다른가? | ✗ | ✓ |
| 기술 요구사항이 다른가? | ✗ | ✓ |
| 독립적으로 배포/확장 가능해야 하는가? | ✗ | ✓ |

## BC 식별 결과

| Bounded Context | 포함 서브도메인 | 유형 | 분리 이유 |
|-----------------|----------------|------|-----------|
| **Attribution** | 귀속 | Core | 전환 이벤트 수신, 귀속 판정/철회. 실시간 판정 엔진 성격 |
| **Commission** | 커미션 | Core | 커미션 산정/확정/취소/차감. 금융 정확성. 완전히 다른 생명주기 |
| **Tracking** | 추적 | Supporting | 링크/쿠폰 발급, 클릭 기록. 단순 CRUD + 리다이렉트 |
| **Partner** | 파트너 | Supporting | 계정, 소속, 티어. CRUD 성격 |
| **Statement** | 정산 명세 | Supporting | 주기 마감, 명세서 집계. 배치 성격 |
| **Tenant** | 테넌트 | Supporting | 고객사 관리, API 키, 프로그램 설정 |
| **Notification** | 알림 | Generic | 웹훅 발송. 외부 서비스 연동 |

## 분리 근거

### 왜 Attribution과 Commission을 분리?

- **생명주기:** 귀속은 전환 이벤트 수신 시 즉시 완료. 커미션은 산정 → 확정 → 정산까지 수주~수개월
- **변경 주기:** 귀속 전략(라스트클릭 등)은 안정적. 커미션 규칙은 자주 변경 (이벤트 기간 등)
- **정확성 요구:** 커미션은 금융 정확성 필수. 귀속은 "맞다/아니다" 판정

### 왜 Tracking을 Attribution에서 분리?

- **역할:** Tracking은 "증거 수집" (링크 발급, 클릭 기록). Attribution은 "판정" (증거 기반 매칭)
- **기술 성격:** Tracking은 고빈도 단순 쓰기 (클릭). Attribution은 조회 + 판정 로직
- **언어:** Tracking에서 "링크"는 URL. Attribution에서 "링크"는 귀속 증거

### 왜 Statement를 Commission에서 분리?

- **생명주기:** Commission은 건별. Statement는 기간별 집계
- **트리거:** Commission은 이벤트 기반 (실시간). Statement는 스케줄러 기반 (배치)
- **변경 주기:** 명세서 포맷/주기는 독립적으로 변경

### 왜 Tenant를 별도 BC로?

- **역할:** 다른 모든 BC가 참조하는 설정의 원천 (Source of Truth)
- **변경 주기:** 설정 변경은 드물지만, 변경 시 여러 BC에 영향
- **독립 배포:** 테넌트 관리는 나머지와 독립적으로 운영 가능

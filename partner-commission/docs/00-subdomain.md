# 00. 서브도메인 분석 (문제 공간)

> "서브도메인은 발견하는 것이고, Bounded Context는 설계하는 것이다."

---

## 도메인 정의

**도메인:** 파트너 커미션 SaaS

고객사(테넌트)의 파트너 추천 프로그램을 운영하는 Headless 서비스.
추적 링크/쿠폰코드를 통해 전환을 귀속하고, 규칙에 따라 커미션을 계산하여 정산 명세를 제공한다.

```
파트너 → 추적 링크 or 쿠폰코드로 추천
소비자 → 클릭/코드 사용 → 고객사 서비스에서 전환 발생
고객사 → 전환 이벤트 전송 → 우리가 귀속 판정 + 커미션 계산 + 명세서 제공
```

---

## 서브도메인 식별

| 서브도메인 | 유형 | 설명 |
|-----------|------|------|
| 귀속 (Attribution) | **Core** | 클릭/쿠폰 기록, 전환 이벤트 수신, 귀속 판정. 이 SaaS의 존재 이유 |
| 커미션 (Commission) | **Core** | 규칙 기반 커미션 산정/확정/취소/차감. 정확성이 핵심 가치 |
| 파트너 (Partner) | Supporting | 파트너 계정(글로벌), 테넌트별 소속/티어 관리. 추후 매칭/추천 시 Core 승격 |
| 정산 명세 (Statement) | Supporting | 정산 주기 마감, 파트너별 명세서 생성 |
| 테넌트 (Tenant) | Supporting | 고객사 등록, API 키, 웹훅 설정, 규칙 설정 |
| 추적 (Tracking) | Supporting | 추적 링크 발급, 클릭 리다이렉트, 추천 코드 발급 |
| 알림 (Notification) | Generic | 웹훅 발송, 이메일 알림 |

## Core Domain 검증

**귀속(Attribution)이 Core인 이유:**

| 질문 | 답 |
|------|-----|
| 이 기능 없으면 비즈니스 존재 가능? | No — 누구의 추천인지 모르면 커미션 계산 불가 |
| 경쟁사도 똑같이? | No — 귀속 전략(라스트클릭/퍼스트클릭), 윈도우, 충돌 해소 규칙이 차별화 |
| 외부 솔루션 대체 가능? | No — 고객사별 설정과 즉시 판정은 직접 구현 필수 |
| 혁신이 가치 창출? | Yes — 정확한 귀속 = 파트너 신뢰 = 생태계 성장 |

**커미션(Commission)이 Core인 이유:**

| 질문 | 답 |
|------|-----|
| 이 기능 없으면 비즈니스 존재 가능? | No — "돈 계산"이 핵심 가치 |
| 경쟁사도 똑같이? | No — 유연한 규칙 엔진(정률/정액/티어/우선순위)이 차별화 |
| 외부 솔루션 대체 가능? | No — 귀속 데이터와 밀접하게 연결 |
| 혁신이 가치 창출? | Yes — 취소 시 자동 회수, 차감 처리가 "돈 잘못 줄 일 없다"의 핵심 |

**파트너(Partner)가 Supporting인 이유:**

| 질문 | 답 |
|------|-----|
| 이 기능 없으면 비즈니스 존재 가능? | No — 파트너 없으면 귀속 대상 없음 |
| 복잡한 도메인 로직이 있나? | No — 등록, 소속, 티어 정도 (CRUD 성격) |
| 경쟁 우위를 만드나? | 현재는 No. 추후 매칭/추천 로직 추가 시 Core 승격 |

---

## Domain Vision Statement

> "우리는 '추천 → 전환 → 커미션'의 정확성을 보장하는 인프라다. 고객사는 전환 이벤트만 보내면 되고, 파트너는 투명한 명세를 받는다. 취소/환불이 끼어도 돈이 잘못 계산되는 일은 없다."

## 투자 전략

| 서브도메인 | 개발 전략 | 설계 수준 |
|-----------|-----------|-----------|
| 귀속 (Core) | 직접 개발, 규칙 엔진 | DDD 전술 패턴 적극 활용 |
| 커미션 (Core) | 직접 개발, 금융 정확성 | DDD 전술 패턴 적극 활용 |
| 파트너 (Supporting) | 직접 개발 | 적절한 DDD |
| 정산 명세 (Supporting) | 직접 개발 | 적절한 DDD |
| 테넌트 (Supporting) | 직접 개발 | 적절한 DDD |
| 추적 (Supporting) | 직접 개발 | 적절한 DDD |
| 알림 (Generic) | 외부 서비스 연동 | 최소 구현 |

## 서브도메인 간 관계 (개략)

```
테넌트 ──설정──→ 귀속 (윈도우, 전략, 충돌 규칙)
테넌트 ──설정──→ 커미션 (규칙, 확정 조건)
테넌트 ──설정──→ 추적 (링크 도메인)

파트너 ──소속──→ 테넌트 (티어, 개별 규칙)

추적 ──클릭/추천코드──→ 귀속 (귀속 증거)
고객사 앱 ──전환 이벤트──→ 귀속 (판정 트리거)
귀속 ──판정 결과──→ 커미션 (산정 트리거)
커미션 ──확정 건──→ 정산 명세 (명세서 생성)
정산 명세 ──완료──→ 알림 (웹훅 발송)

고객사 앱 ──취소 이벤트──→ 귀속 (귀속 철회)
귀속 ──철회──→ 커미션 (취소 or 차감)
```

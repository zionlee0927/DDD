# 07. Context Mapping

> "Context Map은 현재 상태를 있는 그대로 보여줘야 한다. 이상적인 상태가 아니라." — Eric Evans

---

## 식별 과정

### 입력

- 3단계 BC 목록 (7개)
- 2단계 정책 (이벤트 → 커맨드 연결 = BC 간 통신)
- 6단계 Aggregate 간 참조 (ID 참조 = 의존 방향)

### 판단 기준

| 관계의 성격 | 패턴 |
|------------|------|
| 여러 소비자에게 표준 API 제공 | OHS |
| 내부 BC끼리, 동기 호출 | C-S |
| 비동기 이벤트 구독 | Events |
| 외부 시스템 격리 | ACL |
| 설정/정책 제공 | C-S (설정 조회) |

## 관계 상세

| 관계 | 매핑 패턴 | 통신 방식 | 이유 |
|------|-----------|-----------|------|
| 고객사 → Tracking | API (OHS) | 동기 | 링크/코드 발급, 클릭 리다이렉트 |
| 고객사 → Attribution | API (OHS) | 동기 | 전환/취소 이벤트 전송 |
| 고객사 → Statement | API (OHS) | 동기 | 명세서 조회 |
| 고객사 → Tenant | API (OHS) | 동기 | 설정 변경, API 키 관리 |
| Tenant → Attribution | C-S | 동기 | 귀속 판정 시 설정 조회 (윈도우, 전략) |
| Tenant → Commission | C-S | 동기 | 커미션 산정 시 규칙 조회 |
| Tenant → Tracking | C-S | 동기 | 링크 생성 시 설정 조회 |
| Tracking → Attribution | C-S | 동기 | 귀속 판정 시 클릭/코드 데이터 조회 |
| Attribution → Commission | Events | 비동기 | 귀속 판정 → 커미션 산정 |
| Attribution → Commission | Events | 비동기 | 귀속 철회 → 커미션 취소/차감 |
| Commission → Statement | Events | 비동기 | 커미션 확정 → 명세 대상 |
| Statement → Notification | Events | 비동기 | 명세 생성 → 웹훅 발송 |
| Attribution → Partner | C-S | 동기 | 귀속 판정 시 파트너 상태/소속 확인 |

---

## 통신 방식 요약

### 동기 (C-S / OHS)

```
• 고객사 → 우리 API (OHS): 링크 발급, 전환/취소 전송, 명세 조회, 설정 변경
• Tenant → 각 BC (C-S): 설정 조회 (귀속 윈도우, 커미션 규칙 등)
• Tracking → Attribution (C-S): 클릭/코드 데이터 조회
• Attribution → Partner (C-S): 파트너 상태 확인
```

### 비동기 (Events)

```
• Attribution → Commission: 귀속 판정/철회 이벤트
• Commission → Statement: 커미션 확정 이벤트
• Statement → Notification: 명세 생성 이벤트
```

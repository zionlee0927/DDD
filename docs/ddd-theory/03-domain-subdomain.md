# DDD 이론 03: 도메인과 서브도메인

> "모든 소프트웨어 프로그램은 사용자의 어떤 활동이나 관심사와 관련이 있다. 사용자가 프로그램을 적용하는 대상 영역이 소프트웨어의 도메인이다." — Eric Evans

## 1. 도메인과 서브도메인

### 도메인(Domain)
소프트웨어가 해결하고자 하는 **비즈니스 문제 영역**. 이커머스 회사라면 "온라인 상거래", 은행이라면 "금융 서비스".

### 서브도메인(Subdomain)
전체 도메인을 **논리적으로 분리한 하위 영역**. 대부분의 도메인은 너무 크고 복잡해서 하나의 모델로 다룰 수 없기 때문에 분리한다.

---

## 2. 서브도메인의 세 가지 유형

> "모든 서브도메인이 동등하게 중요한 것은 아니다. 어떤 것은 비즈니스의 핵심이고, 어떤 것은 지원 역할을 하며, 어떤 것은 범용적이다." — Vaughn Vernon

### Core Domain (핵심 도메인)

비즈니스의 **핵심 경쟁력**. 회사가 존재하는 이유이자 차별화 요소.

**특징:**
- 비즈니스 성공에 직접적 영향
- 경쟁사와 차별화되는 영역
- 복잡하고 자주 변경됨
- 외부에서 구매할 수 없음

**투자 전략:**
- 최고의 개발자 배치
- DDD 전술적 패턴 적극 활용
- 지속적인 모델 정제
- 절대 외주나 패키지로 대체 금지

**예시:** 넷플릭스의 추천 알고리즘, 아마존의 물류 최적화, 쿠팡의 로켓배송

### Supporting Subdomain (지원 서브도메인)

Core Domain을 **지원하는 역할**. 비즈니스에 특화되어 있지만 핵심 경쟁력은 아님.

**특징:**
- 비즈니스에 필요하지만 차별화 요소 아님
- 회사 특화 로직 포함 (기성 솔루션으로 대체 어려움)
- 중간 정도의 복잡성

**투자 전략:**
- 적절한 수준의 설계
- 필요시 외주 개발 가능
- 과도한 투자 지양
- 단순한 DDD 패턴 적용

**예시:** 이커머스의 리뷰 시스템, 포인트 적립, 알림 발송

### Generic Subdomain (범용 서브도메인)

**모든 비즈니스에 공통적**으로 필요한 영역. 표준적인 솔루션 사용 가능.

**특징:**
- 산업 전반에 공통적
- 표준화된 솔루션 존재
- 비즈니스 차별화와 무관
- 잘 알려진 문제 영역

**투자 전략:**
- 기성 솔루션/SaaS 활용 (Auth0, Stripe, SendGrid 등)
- 오픈소스 라이브러리 사용
- 직접 개발 최소화
- 단순 CRUD로 충분

**예시:** 인증/인가, 결제(PG사), 이메일 발송, 파일 저장

## 3. Distillation: 핵심 도메인 증류하기

> "Distillation은 혼합물에서 가치 있는 물질을 분리하는 과정이다. 모델도 마찬가지로 핵심을 추출하고 부수적인 것을 분리해야 한다." — Eric Evans

### Core Domain 식별 질문

| 질문 | Core 시그널 |
|---|---|
| "이 기능이 없으면 비즈니스가 존재할 수 있는가?" | 없으면 불가능 → Core |
| "경쟁사도 똑같이 할 수 있는가?" | 쉽게 따라할 수 있음 → Core 아님 |
| "외부 솔루션으로 대체할 수 있는가?" | 대체 불가 → Core, 대체 가능 → Generic |
| "이 영역에서 혁신이 비즈니스 가치를 창출하는가?" | 직접적 가치 → Core |

### Domain Vision Statement

Core Domain이 무엇이고 왜 중요한지를 **한 페이지로 설명**하는 문서.

예시 (음식 배달 플랫폼):
> "우리의 핵심 경쟁력은 실시간으로 최적의 배달 경로와 라이더를 매칭하는 것이다. 주문 위치, 음식점 위치, 라이더 현재 위치, 교통 상황, 음식 조리 시간을 종합적으로 고려하여 가장 빠르고 효율적인 배달을 가능하게 한다."

### Highlighted Core

코드베이스에서 Core Domain을 **패키지 구조로 명확히 표시**하여 개발자들이 어디에 집중해야 하는지 알 수 있게 한다.

```
com.company.delivery/
├── core/                    // ⭐ CORE DOMAIN
│   ├── routing/            // 배달 경로 최적화
│   └── pricing/            // 동적 가격 책정
├── supporting/              // Supporting
│   ├── review/
│   ├── notification/
│   └── promotion/
└── generic/                 // Generic
    ├── auth/
    ├── payment/
    └── storage/
```

## 4. 전략적 투자 매트릭스

| 항목 | Core | Supporting | Generic |
|---|---|---|---|
| 개발 방식 | 내부 개발 필수 | 내부 또는 외주 | 구매/SaaS/오픈소스 |
| 인력 배치 | 최고 인재 | 적절한 수준 | 최소 인력 |
| 설계 수준 | DDD 전술적 패턴 | 단순 DDD 또는 트랜잭션 스크립트 | CRUD / 외부 API |
| 테스트 | 철저한 단위/통합 테스트 | 적절한 테스트 | 통합 테스트 위주 |
| 리팩토링 | 지속적 개선 | 필요시 | 거의 안함 |

### 흔한 실수: 모든 곳에 DDD 적용

- ❌ 인증, 결제, 파일 업로드 같은 Generic에 복잡한 DDD 패턴 적용 → 불필요한 복잡성, 시간 낭비
- ✓ Generic은 검증된 외부 솔루션 사용, 절약한 시간을 Core에 투자

> "Core Domain에 집중하라. 그것이 당신의 비즈니스를 차별화하는 것이다. 나머지는 가능한 한 단순하게 유지하거나 외부 솔루션을 활용하라." — Vaughn Vernon

## 5. 서브도메인의 진화

> "서브도메인의 분류는 고정된 것이 아니다. 비즈니스 전략이 변하면 어제의 Generic이 오늘의 Core가 될 수 있다." — Vaughn Vernon

### 유형 변화 사례

**Generic → Core: 아마존의 물류**
- 초기: 외부 물류 업체에 배송 위탁 (비용 센터)
- 현재: 자체 물류 네트워크 구축, 당일/익일 배송이 핵심 경쟁력

**Core → Supporting → 폐지: 넷플릭스의 DVD 배송**
- 초기: DVD 우편 배송이 핵심 비즈니스
- 현재: 스트리밍이 Core가 되면서 DVD 사업 분리/폐지

**Supporting → Core: 스타벅스의 모바일 주문**
- 초기: 편의 기능으로 시작
- 현재: 전체 주문의 25%+, 리워드 프로그램과 결합된 핵심 경쟁력

### 진화에 대응하는 방법

1. **정기적 재평가** — 분기별 서브도메인 분류 리뷰, 비즈니스 전략 변화 모니터링
2. **유연한 아키텍처** — Bounded Context로 명확한 경계, 느슨한 결합으로 교체 용이성
3. **전환 대비** — Generic에서 Core로 전환 가능한 구조 유지

## 6. 실제 기업 사례

### 쿠팡

| 유형 | 서브도메인 |
|---|---|
| Core | 로켓배송 물류 시스템, 쿠팡맨 매칭/경로 최적화 |
| Supporting | 상품 카탈로그, 리뷰, 고객 서비스, 판매자 관리, 프로모션 |
| Generic | 결제(PG), 인증, 알림, 검색(Elasticsearch) |

### 스포티파이

| 유형 | 서브도메인 |
|---|---|
| Core | 음악 추천 엔진(Discover Weekly), 오디오 스트리밍 기술 |
| Supporting | 플레이리스트 관리, 아티스트 프로필, 소셜 기능, 팟캐스트 |
| Generic | 결제/구독, 인증, 알림, 광고 플랫폼 |

---

## 핵심 정리

1. 서브도메인은 **Core, Supporting, Generic**으로 분류된다
2. Core Domain은 비즈니스의 핵심 경쟁력 — 최고 인재, 최대 투자
3. Generic은 외부 솔루션 활용 — 직접 개발 최소화
4. **Distillation**으로 핵심을 식별하고 분리한다
5. 분류는 고정이 아님 — 비즈니스 전략에 따라 **진화**한다
6. 분기별 재평가, 유연한 아키텍처로 전환에 대비

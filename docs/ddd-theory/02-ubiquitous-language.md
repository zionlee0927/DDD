# DDD 이론 02: 유비쿼터스 언어

## 핵심 개념

프로젝트의 모든 곳(대화, 문서, 다이어그램, 코드)에서 일관되게 사용되는 공유 언어.

### Translation Chain 문제
도메인 전문가 → 요구사항 → 명세서 → 설계 → 코드. 각 단계에서 의미 손실 발생.

## 언어 구축 5단계

1. **수집** — 도메인 전문가와 대화, 기존 문서에서 용어 추출
2. **정의/합의** — 팀 전체가 용어의 의미에 합의
3. **용어집 작성** — 공식 문서화
4. **코드 반영** — 클래스명, 메서드명에 용어 그대로 사용
5. **지속적 정제** — 새로운 이해가 생기면 언어 업데이트

## 용어집 구성

용어(한국어), 영문 매핑, 정의, 관련 용어, 코드 매핑, 불변식

## Intention-Revealing Interface

```
❌ process(), doIt(), handle()
✓ confirm(), cancel(reason), markAsPaid()
```

## 유비쿼터스 언어와 Bounded Context

- 유비쿼터스 언어는 Bounded Context 내에서만 유효
- 같은 용어라도 다른 Context에서는 다른 의미
- Context 간 통신 시 ACL에서 명시적 번역

## 안티패턴

- 개발자만의 언어 사용
- 용어집 작성 후 방치
- 영어 강제 (도메인 전문가가 한국어 사용 시)
- 모호한 용어 방치
